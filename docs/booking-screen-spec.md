# 예약 화면 구현 명세 (개발자용)

2026-09-27 · 초안 v0.1

## 이 문서를 읽는 법

여백 미장원 웹사이트의 예약 화면, 후기 작성 화면, 공통 하단 영역의 구현 명세입니다. UI 디자인이 아니라 법적 요건을 정리한 것입니다. 회원가입이 없는 서비스라서 개인정보 동의는 예약 화면에서 받습니다.

### 표시 규칙

| 표시 | 의미 |
| --- | --- |
| [법정] | 법적 요건. 임의로 바꾸면 동의 자체가 무효가 되거나 과태료 대상입니다. 변경이 필요하면 기획자에게 확인하세요 |
| (권장) | 법적 의무는 아니지만 분쟁 예방을 위해 넣는 것 |
| [미정] | 아직 확정되지 않은 값. 확정 전까지 하드코딩하지 마세요 |

### 왜 이렇게까지 하는가

동의 화면은 잘못 만들면 받은 동의가 통째로 무효가 됩니다. 체크박스를 미리 체크해두거나, 전문 링크를 빼거나, 입력부터 받고 동의를 나중에 받으면 그렇습니다. 동의가 무효면 그동안 받은 예약 정보 전체가 동의 없이 수집한 정보가 됩니다.

### 관련 문서

이 명세는 아래 문서를 근거로 합니다. 문구가 서로 다르면 아래 문서가 우선입니다.

- 이용약관 초안 (`docs/terms-of-service.md`)
- 개인정보처리방침 초안 (`docs/privacy-policy.md`)
- 운영정책 초안 (`docs/operation-policy.md`)

공개용 화면(`terms.html`, `privacy.html`, `policy.html`)은 위 Markdown에서 `python docs/build_legal_pages.py`로 생성합니다. 화면 HTML을 직접 고치지 말고 Markdown을 고친 뒤 다시 생성하세요.

## 화면 흐름

```
01 날짜 선택 → 02 시간 선택 → 03 예약자 정보 입력 → 동의 → [예약 및 결제 신청]
   → 접수 완료 안내(모달) → 서버: 동의 이력 기록, 캘린더 등록, 접수 알림톡
```

### 동의 위치에 관하여

회원가입 서비스는 동의를 맨 앞에 두지만, 이 화면은 입력 필드 바로 아래, 신청 버튼 바로 위에 둡니다. 입력값은 [예약 및 결제 신청]을 누르기 전까지 어디에도 전송·저장되지 않으므로, 전송 시점 이전에 동의를 받으면 됩니다. [법정]

따라서 신청 버튼 이전에 입력값을 서버로 보내는 기능(자동 저장, 입력 중 전송)을 추가하면 안 됩니다. 연락처 입력 시 보유 코인 조회는 브라우저 안의 데이터만 보므로 해당하지 않습니다. 서버 조회로 바꾸면 동의를 먼저 받아야 합니다.

## 동의 영역

### 체크박스 구성 [법정]

| # | 문구 (그대로 사용) | 필수 | 전문 링크 |
| --- | --- | --- | --- |
| 1 | (필수) 예약자는 만 14세 이상입니다 | 필수 | 없음. 옆에 "만 14세 미만은 보호자 명의로 예약해 주세요" 안내 |
| 2 | (필수) 이용약관과 예약 취소 규정에 동의합니다 | 필수 | `terms.html` 새 창 |
| 3 | (필수) 개인정보 수집·이용에 동의합니다 | 필수 | 요약 표 펼치기 + `privacy.html` 새 창 |

### 배치 규칙 [법정]

- 모든 체크박스의 초기 상태는 해제입니다. 예약 완료 후 폼을 초기화할 때도 해제 상태로 돌아가야 합니다
- 약관 동의와 개인정보 동의를 하나의 체크박스로 합치지 않습니다
- 2, 3번에는 전문을 볼 수 있는 링크를 각각 답니다. 전문은 새 창으로 열어 예약 화면의 입력값과 체크 상태가 유지되게 합니다
- 동의 문구 글자 크기를 본문보다 작게 하지 않습니다 (14px 이상)

### 3번 펼침 내용: 개인정보 수집·이용 동의 [법정]

개인정보처리방침 전체가 아니라 아래 요약 표를 보여줍니다.

| 수집 항목 | 이용 목적 | 보유 기간 |
| --- | --- | --- |
| 이름, 연락처 | 예약 확인, 예약 안내 알림, 코인 적립·사용 | 최근 방문일로부터 3년 |
| 예약 일시, 시술 메뉴, 담당 디자이너, 요청 사항 | 예약 처리 | 최근 방문일로부터 3년 |
| 동의 일시, 접속 IP, 브라우저 정보 | 동의 사실 증명 | 3년 |

표 아래에 이 문장을 반드시 넣습니다. 없으면 동의가 무효가 될 수 있습니다.

> 동의를 거부할 권리가 있습니다. 다만 동의하지 않으시면 온라인 예약이 제한되며, 전화(031-123-4567)로 예약하실 수 있습니다.

그 아래에 알림 발송 위탁 사실과 개인정보처리방침 전문 링크를 둡니다.

> 예약 안내 알림 발송을 위해 솔라피·카카오에, 예약 일정 관리를 위해 네이버에 처리를 위탁합니다.

### 신청 버튼 활성화 조건

```
활성화 = (1번 체크) AND (2번 체크) AND (3번 체크)
```

비활성 상태에서도 버튼 문구 아래에 "필수 항목에 동의해 주세요"를 보여 이유를 알 수 있게 합니다. (권장) 날짜·시간 미선택 검사는 기존대로 제출 시 안내합니다.

### 광고성 정보 수신 동의

현재는 두지 않습니다. 광고성 알림을 보내기로 하면 4번 (선택) 체크박스를 추가하고, 이 체크박스는 신청 버튼 활성화 조건에 넣지 않습니다. [법정]

## 동의 이력 저장 [법정]

동의 여부만 true로 저장하면 안 됩니다. 언제, 어떤 버전의 문서에, 어떤 경로로 동의했는지가 남아야 합니다.

### 클라이언트 → 서버

예약 객체에 `consent`를 붙여 `POST /api/reservations`로 보냅니다.

```
consent: { version: "2026-09-27", agreedAt: "2026-10-01T05:12:00.000Z", items: ["age14", "terms", "privacy"] }
```

`version`은 `app.js`의 `LEGAL_VERSION` 상수 한 곳에서만 관리합니다. 약관이나 방침을 개정하면 이 값과 문서의 개정일을 함께 바꿉니다.

### 서버 저장 필드

서버는 동의 항목마다 한 줄씩 `naver-store.json`의 `consents` 배열에 추가합니다.

| 필드 | 설명 |
| --- | --- |
| reservation_id | 예약 id |
| phone | 연락처 (숫자만) |
| consent_type | age14, terms, privacy |
| agreed | true |
| agreed_at | 클라이언트 동의 시각 |
| recorded_at | 서버 수신 시각 |
| document_version | 동의한 문서 버전 |
| ip_address | 접속 IP (`X-Forwarded-For` 우선) |
| user_agent | 브라우저 정보 (200자까지) |
| channel | booking |

### 규칙

- `consent.items`에 age14, terms, privacy가 모두 없으면 서버는 400을 반환하고 예약을 처리하지 않습니다
- 이력은 덮어쓰지 않고 추가만 합니다. 같은 예약 id로 다시 들어오면 추가하지 않습니다
- 동의 이력은 `recorded_at`으로부터 3년이 지나면 자동 삭제합니다 (방문 안내 배치와 같은 주기)

## 후기 작성 화면

### 안내 문구 [법정]

후기 본문 입력란 아래에 다음 문구를 표시합니다.

> 후기는 누구나 볼 수 있으며 이름은 첫 글자만 공개됩니다. 다른 사람의 이름이나 연락처 등 개인정보는 적지 마세요.

### 공개 범위 [법정]

후기 목록에 표시하는 이름은 첫 글자 + `**`입니다. 전체 이름은 관리자 화면에서만 보입니다. 화면에서 가리는 것뿐 아니라, 후기를 서버 API로 제공하게 되면 응답 자체에서 이름을 가려서 보내야 합니다.

## 절대 하면 안 되는 것 [법정]

### 동의가 무효가 되는 구현

- 체크박스를 미리 체크된 상태로 제공
- 약관 동의와 개인정보 동의를 하나의 체크박스로 통합
- 전문 보기 링크 없이 문구만 표시
- "동의를 거부할 권리가 있다" 문구 누락
- 동의 문구 글자 크기를 본문보다 작게 표시
- 신청 버튼을 누르기 전에 입력값을 서버로 전송

### 법 위반이 되는 구현

- 요청 사항에 건강 정보 기재를 유도
- 후기 목록에 작성자 전체 이름 노출
- 알림톡 템플릿에 광고성 문구 포함
- 개인정보처리방침 링크를 하단에서 제거

### 운영상 문제가 되는 구현

- 동의 여부를 boolean 하나로만 저장 (이력 미보관)
- 동의 이력 덮어쓰기
- 문서 버전을 여러 곳에 하드코딩
